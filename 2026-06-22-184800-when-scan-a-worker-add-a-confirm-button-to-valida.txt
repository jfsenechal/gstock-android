● Build is green. Here's what I changed.

  Summary

  1. Confirm button for the worker scan

  The checkout flow used to jump straight from scanning a worker's badge to the
  tools step. I added an intermediate CONFIRM_WORKER step:

  - CheckoutViewModel.kt — added CONFIRM_WORKER to the CheckoutStep enum. A
  successful worker scan now lands on this step (holding the worker in state)
  instead of auto-advancing. Added confirmWorker() (→ SCAN_TOOLS) and
  rescanWorker() (→ back to SCAN_WORKER, clearing the worker) so a mis-scan can
  be corrected.
  - CheckoutScreen.kt — added a ConfirmWorkerStep composable showing the scanned
  worker's card (reusing the existing WorkerHeaderCard) with a Confirm button
  and a Scan again button, plus a preview.

  2. Scan sound

  - New core/ScanSoundPlayer.kt — a @Singleton that emits a short beep via
  ToneGenerator (no sound asset needed, construction guarded so it silently
  no-ops if audio is unavailable).
  - Injected into CheckoutViewModel; playSuccess() fires on a successful worker
  scan and on each successfully added tool.

  3. Strings — added checkout_confirm_worker_title,
  checkout_confirm_worker_instruction, checkout_confirm_worker, and
  checkout_scan_again in both values/strings.xml (English) and
  values-fr/strings.xml (French), per the localization convention.

  One note: the beep plays whenever the camera decodes a valid Gstock
  worker/tool QR and the server resolves it — it won't beep on unrecognized
  codes or already-reserved tools (those surface an error/dialog instead). If
  you'd rather have feedback on every decode, that'd move into QrScannerView;
  let me know.

  What changed (QrScannerView.kt)

  The analyzer no longer reports the first barcode it happens to find. Now, per
  frame it:

  1. Picks the centered code — among decoded barcodes, the one whose
  bounding-box center is nearest the frame center, and only if it falls within a

  2. Debounces by dwell time — that code must stay the centered one for
  CENTER_DWELL_MS = 400ms before it's reported. Panning the camera across a
  sheet keeps resetting the dwell timer, so a lookup only fires once the user
  settles the reticle on a code.
  3. Keeps the existing SCAN_COOLDOWN_MS = 2500 repeat-guard so holding on one
  code doesn't re-fire.

  I also handle the 90°/270° rotation case (ML Kit reports bounding boxes in the
  upright image space, so the width/height are swapped to compute the center
  correctly), and added a small helper for the squared-distance comparison.

  Plus a center reticle — a rounded white square (60% width) drawn over the
  preview so the user can see exactly where to aim. This applies to both the
  worker and tool scan screens since they share QrScannerView.

  the 0.6f reticle doesn't line up with how it feels in the hand — let me know
